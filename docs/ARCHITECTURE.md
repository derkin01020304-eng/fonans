# Архитектура

Стек: Flutter 3.35.7, Dart 3.9.2, Material 3, Riverpod 2.6.1, GoRouter 14.8.1, SQLite с SQLCipher, json_serializable. Для графиков используются собственные Flutter CustomPainter: дополнительных сервисов или графических API не требуется.

Применено разделение по слоям Clean Architecture. Домен не импортирует Flutter. Модели сериализуются через json_serializable; генерация Freezed не требуется. UI получает снимки состояния через Riverpod. FinanceRepository описывает операции учёта; SqlFinanceRepository реализует атомарные сценарии. В MVP runtime и интеграционные сервисы получают конкретный SQLite-репозиторий для общей транзакционной границы. Для смены хранилища эти адаптеры потребуется заменить.

## Потоки данных

UI → формы и валидация → репозиторий → SQLite-транзакция → инвалидирование snapshotProvider → аналитика и виджеты.

Банк → BankProvider → сбор всех страниц → категоризация → SQLite-транзакция → журнал и снимки банка.

AI/MCP → токен и scope → JSON Schema → FinanceAssistantAPI → репозиторий → запись requestId и результата в той же SQLite-транзакции.

Ни AI, ни внешние клиенты не получают SQL-соединение или произвольный SQL-инструмент.

## Схема данных

| Таблица | Содержание и связи |
|---|---|
| transactions | Вид движения, сумма minor, валюта, accountId, toAccountId, дата/время, категория/подкатегория, источник, получатель, комментарий, часы в минутах, MCC, метод, externalKey, linkType/linkId |
| accounts | Имя, тип, валюта, начальный остаток, резерв, связь с банком |
| debts | Направление, контрагент, первоначальная сумма, остаток, даты и комментарий |
| debt_payments | Сумма, дата, долг parentId, транзакция |
| credits | Банк, суммы, ставка в базисных пунктах, ежемесячный платёж, даты, уплаченные проценты, paymentDay |
| credit_payments | Основной долг и проценты отдельно, дата, parentId и проводки |
| savings | Изменение накоплений со знаком, transactionId, необязательный goalId |
| goals | Название, целевая сумма, валюта и срок; накопленное вычисляется из savings |
| recurring_payments | Сумма, резерв, валюта, счёт, частота, срок, anchorDay |
| categories | Справочник категорий |
| bank_connections | Метаданные соединения и последний sync; без OAuth-секретов |
| category_rules | Подтверждённая категория нормализованного получателя |
| bank_snapshots | Последний заявленный баланс банка и время снимка |
| api_requests | Идемпотентность записи AI: requestId, tool, hash аргументов и результат |
| audit_log | Время и имя записывающего инструмента без содержимого запроса |
| settings | Локальные флаги демо и сохранённое состояние до демо |

Схема создаётся миграциями `assets/schema_v1.sql` и `assets/schema_v2.sql`. Текущая версия — 2. Вторая миграция добавляет правила, банковские снимки, журнал API и сохраняемый день кредитного платежа. Миграция v1 → v2 проверяется тестом.

Новую миграцию оформляйте отдельным `schema_v3.sql`, зарегистрируйте asset и увеличьте FinanceDatabase.version. При изменении формата резервной копии добавьте явное преобразование версии; текущая реализация принимает только schemaVersion 2.

## Инварианты

- Суммы: int, положительные для операции; направление кодируется видом движения. SavingsEntry может быть отрицательным при снятии.
- Один перевод — одна запись transactions с двумя разными счетами одной валюты.
- Перевод в накопления добавляет связанную запись savings. Перевод из накоплений уменьшает соответствующую цель или нераспределённые накопления.
- Расходование непосредственно с накопительного счёта ограничено: сначала переведите деньги на обычный счёт.
- При погашении долга одновременно меняется его остаток, добавляются debt_payments и проводка.
- При погашении кредита одновременно меняются остаток/проценты/дата, записываются credit_payments, проводка тела и отдельный расход процентов.
- Отрицательные балансы обычных счетов допускаются: это позволяет внести историю до настройки начальных остатков. Накопления нельзя снимать сверх остатка.
- Смена валюты или типа счёта с историей запрещена. Удаление связанных сущностей защищено внешними ключами и прикладными проверками.
- При неудачном импорте, восстановлении или выплате SQLite откатывает весь сценарий.
- Для дат месяца сохраняется исходный день: 31 января → 28 февраля → 31 марта.
- Исторические долги на графике восстанавливаются из текущего остатка и записанных погашений. Ранее не внесённые движения не выдумываются.

## Расширение

Новый банк реализует BankProvider и добавляется в список экрана интеграций. Банк со сложной FAPI/mTLS-авторизацией требует своего backend-адаптера.

Новый инструмент AI добавляется в assets/mcp_tools.json, список readTools или writeTools и диспетчер FinanceAssistantAPI. Затем добавьте проверку scope, схему и тест запрета неразрешённого вызова. Запись обязательно выполняется внутри существующей транзакционной границы идемпотентности.

Облачная синхронизация отсутствует. Для её добавления нужны версия/конфликты объектов, журнал изменений, E2EE-ключи устройств и отдельный механизм восстановления ключей; обычный экспорт JSON не является облачной синхронизацией.
