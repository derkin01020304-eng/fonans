# Изменения

## 0.1.1+2 — исправление запуска

- Исправлен вызов `PRAGMA secure_delete = ON`: настройка возвращает строку результата, поэтому используется `rawQuery`. Android-драйвер SQLCipher не допускает такие запросы через `execSQL`, который использует `execute`.
- Повторный запуск выполняется одной попыткой; при ошибке после открытия соединение закрывается. Существующие база, ключ и данные не сбрасываются, версия схемы остаётся 2.
- Экран сбоя показывает этап и копируемый код без SQL, ключей или финансовых данных. Ошибки загрузки других компонентов больше не обозначаются безусловно как сбой защищённого хранилища.
- Скриншоты разрешены по запросу владельца.
- Тесты SQLite используют общую с приложением настройку базы. Добавлены проверка Android-контракта PRAGMA, безопасной диагностики и повторного запуска.
- Нативный интеграционный тест теперь проверяет настоящие миграции, начальные счета, запись операции и повторное открытие зашифрованной базы. Подготовленный GitHub Actions workflow запускает его на Android API 35 до сборки APK.

Это исправление найденной в исходниках причины сбоя. Причина ошибки именно в установленном пользователем APK ещё не подтверждена журналом устройства; нативный тест и новая APK-сборка требуют доступа к репозиторию/Android-среде. Фактически выполненные проверки перечислены в `VERIFICATION.md`.

Техническое основание: [контракт SQLite PRAGMA](https://sqlite.org/pragma.html#pragma_secure_delete), [описание ограничения Android SQLCipher](https://github.com/sqlcipher/sqlcipher-android/issues/6). Настройка эмулятора следует [документации Android Emulator Runner](https://github.com/ReactiveCircus/android-emulator-runner).
