## Что покрывают тесты

- Точное преобразование денег и границы дат.
- Сохранение общего баланса при переводах.
- Пополнение/снятие накоплений и остаток цели.
- Сохранение банковского externalKey при переводе в накопления.
- Запрет переводов между разными валютами и одинаковыми счетами.
- Изменение/удаление обычной операции без накопления ошибок баланса.
- Частичное погашение долга и запрет переплаты.
- Возврат долга без ложного дохода.
- Раздельный учёт тела кредита и процентов.
- Атомарный rollback при ошибочном счёте или восстановлении.
- Сохранение 31-го дня платежа после февраля.
- Все еженедельные платежи в горизонте 30 дней.
- Однократное вычитание зарезервированной суммы.
- Почасовой доход только по операциям с указанным временем.
- Приоритет подтверждённой категории.
- Вход и выход из демо с сохранением первоначального состояния.
- CSV, XLSX, OFX; десятичная запятая, часовые пояса, ошибочные строки.
- Повтор выписки и повтор одинаковых строк без банковского ID.
- Идемпотентность mock-банка и согласование начального остатка.
- AES-GCM: расшифровка, неверный пароль, изменение ciphertext.
- Миграция базы v1 → v2.
- JSON Schema: целые суммы, диапазоны, неверные даты и лишние поля.
- API: запрет доступа без разрешения, запрет повышения scope, отзыв токена.
- Повторный параллельный requestId создаёт только одну операцию.
- MCP: initialize, scoped tools/list, structuredContent, отказ чужому Origin, неверному токену и GET.
- PIN: соль/верификатор, смена PIN, блокировка после пяти неудачных попыток.
- Уход в фон во время проверки PIN не разблокирует приложение.
- Блокировка через две минуты отзывает разрешение AI.
- Навигация на экране шириной 320 px и реальное сохранение расхода через UI на 390 px.
- Настройка базы через общий с приложением код; Android-контракт запрещает выполнять возвращающий строки PRAGMA через execute. FFI-адаптер воспроизводит именно это ограничение драйвера.
- Коды ошибок запуска не раскрывают SQL и ключи из нативного исключения.
- Экран ошибки отображает копируемый код и позволяет повторить запуск.

## Ограничения проверки

Стандартный `flutter analyze` не завершился из-за SIGBUS в snapshot analysis server SDK на файловой системе этой среды. Вместо него выполнен `dart run scripts/analyze_local.dart`, использующий библиотеку analyzer и проверяющий типы, ошибки и предупреждения. Этот fallback **не регистрирует Flutter lint rules**. Поэтому в обычной среде дополнительно выполните:

    flutter analyze --no-fatal-infos

Ошибки и предупреждения остаются блокирующими; информационные stylistic lint-сообщения не блокируют предоставленные сценарии сборки.

**Исправленные APK/AAB 0.1.1+2 не собраны.** Android SDK отсутствовал, публичная загрузка command-line tools возвращала HTTP 404. Подключённый GitHub-аккаунт обнаружен, но списки доступных репозиториев и установок приложения пусты: изменения в удалённый репозиторий не внесены, Actions не запущен. Пользователь сообщил об установке предыдущего APK; его исходный commit и журнал запуска пока недоступны. Нативная Gradle/JNI-компиляция и установка исправления на телефон из этой среды не подтверждены.

Не запускались: нативный тест SQLCipher/Keystore, биометрия на устройстве, OAuth реального банка, системные файловые диалоги, listener банковских уведомлений, перезагрузка с восстановлением alarms, Google Play-публикация и GitHub Actions workflow.

## Проверка Android при сборке

    flutter doctor -v
    flutter pub get
    flutter analyze --no-fatal-infos
    flutter test
    flutter test integration_test/android_storage_test.dart -d DEVICE_ID
    flutter build apk --release

Нативный интеграционный тест использует собственный временный SQLCipher-файл и отдельный тестовый ключ защищённого хранилища. В 0.1.1 он открывает базу через настоящий FinanceDatabase.openEncrypted, применяет общие настройки и миграции, создаёт начальные счета и записывает операцию. Проверяет PRAGMA cipher_version, foreign_keys и secure_delete, отсутствие обычного SQLite-заголовка, сохранность операции после повторного открытия и очистку только тестовых данных. Этот тест подготовлен, но в текущей среде не запускался.

Workflow `.github/workflows/android.yml` теперь включает эмулятор Android API 35 и требует успешного нативного теста перед сборкой APK. YAML разобран локально; порядок шагов проверен. Успешное выполнение удалённого workflow ещё не подтверждено.

Инструкции установки SDK и подписи APK находятся в README.md. Внешние банковские/AI credentials в проекте отсутствуют. Реальный банк, PDF/OCR и облачная синхронизация не заявлены как выполненные интеграции.
